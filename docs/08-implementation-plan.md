## المبادئ الحاكمة للتنفيذ

1. **طبقة الـ Repository هي الفاصل الوحيد.** كل الشاشات تستورد من `lib/data` و
   `lib/auth`. التحويل من Mock إلى Supabase يلمس هذه الطبقة فقط — لا تُكتب استعلامات
   مباشرة في الشاشات.
2. **المنطق الحرج في قاعدة البيانات.** Status Engine وحسابات Payroll كـ Postgres
   functions تحت RLS — لا يُكرَّر في الواجهة.
3. **RLS غير قابل للتفاوض.** كل جدول جديد يصدر بسياسة `tenant_id` من اليوم الأول؛
   لا migration بدون اختبار RLS مصاحب.
4. **كل جلسة تنتهي بمخرج قابل للاختبار** (نفس عمود "المخرج" في خارطة الطريق).
5. **اختبار مع كل موديول، لا في النهاية:** Unit للحسابات، RLS tests للعزل،
   E2E للمسار الحرج.

## ما بعد الـ MVP (Phase 2 → Phase 3)

| Phase 2 | Phase 3 |
|---|---|
| Assets (عهدة بدورة حياة) | ATS Portal عام لكل Tenant |
| Training & HSE Certs (مصفوفة تجديد) | Manpower Planning بالمشروع |
| Probation & Contracts (تنبيهات) | Advanced Analytics |
| Performance (دورات تقييم) | eSignature معتمد + Org Chart تفاعلي |
| Disciplinary (مرتبط بالـ Payroll) | AI Copilot عربي كامل على بيانات الـ Tenant |

## المخاطر المفتوحة (تُحسم قبل جلستها)

1. **SLA الفرز (P1):** اعتماد "5 أيام عمل" رسمياً — قبل المرحلة 2.
2. **WhatsApp Business API:** يتطلب Meta Business موثق وقوالب — يبدأ مبكراً جداً (دورة اعتماد طويلة).
3. **جداول الضرائب والتأمينات:** تتغير سنوياً — تُبنى قابلة للتحديث وتُراجع مع محاسب — قبل المرحلة 6.
4. **مزود SMS مصري:** اختيار وتعاقد — قبل المرحلة 9.
5. **تقويم Payroll:** قابل للتهيئة لكل Tenant بقيم الدليل افتراضياً (18/19/23/25/28/10).
