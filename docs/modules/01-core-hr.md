مصدر واحد للحقيقة لبيانات الموظف. كل الموديولات الأخرى تقرأ منه وتكتب فيه.

## الكيانات والبيانات

(الجداول التفصيلية في [نموذج البيانات §2](../02-data-model.md))

### Employee Master Record
- **الهوية:** HR Code (توليد تلقائي بصيغة قابلة للتهيئة لكل Tenant — مثل `AFR-{YYYY}-{####}` — فريد **ولا يُعاد استخدامه** أبداً حتى بعد الأرشفة)، الاسم عربي/إنجليزي، الرقم القومي (14 رقماً + Validation خوارزمي + استخراج تاريخ الميلاد والنوع والمحافظة تلقائياً)، الموبايل، الإيميل الشخصي والشركة، الصورة، العنوان، الحالة الاجتماعية، جهة اتصال الطوارئ
- **التوظيف:** المسمى، الدرجة (Grade)، القسم، المدير المباشر، نوع التوظيف (دائم/مؤقت/مشروع)، White/Blue Collar، تاريخ التعيين، تاريخ توقيع العقد، حالة الموظف
- **المالية** (جدول منفصل بصلاحيات مشددة): الراتب الصافي/الإجمالي/التأميني، البدلات، رقم التأمين الاجتماعي، البنك والحساب مع علامة **Verified** (اشتراط Policy 6 — لا دفعة بدون تحقق)
- **المشروع:** ربط الموظف بمشروع واحد أو أكثر بنسب تحميل تكلفة (Cost Allocation % — مجموعها 100) + موقع العمل

سجل زمني Append-only لكل تغيير: ترقية، نقل مشروع، تعديل راتب، جزاء، تجديد عقد، تغيير حالة — مع المرفقات ومرجع الاعتماد.

## الوظائف

1. إنشاء الموظف تلقائياً من Onboarding + إدخال يدوي + **استيراد Excel للـ Migration** (قالب جاهز + معالجة أخطاء صف-بصف + Dry-Run قبل الالتزام)
2. **Status Engine:** `Pending → Active → Suspended → Offboarding → Archived`. التحول لـ Active محكوم بدالة تحقق من شروط التفعيل الستة (مستندات مكتملة + عقد موقع + متطلبات HSE + فحص طبي + أنظمة جاهزة + شهادات) — **ولا يدخل Payroll قبل Active** (تطبيق Policy 1 كقيد قاعدة بيانات لا مجرد تنبيه)
3. بحث وفلترة متقدمة: مشروع / موقع / حالة / قسم / Collar / مستندات منتهية أو ناقصة
4. **صلاحيات على مستوى الحقل:** الراتب لأدوار Payroll وHR Manager وFinance فقط (Policy 9) — معزول في جدول مستقل بـ RLS خاص
5. **Audit Log كامل** لكل تعديل: مَن، متى، القيمة قبل وبعد (Policy 16)
6. منع التكرار بالرقم القومي + **كشف الـ Rehire تلقائياً:** رقم قومي لموظف مؤرشف → تنبيه بعرض تاريخه السابق (بما فيه سبب الخروج)
7. **أرشفة فقط — لا حذف نهائي** (Policy 14)

## الأتمتة والذكاء الاصطناعي

- **OCR للمستندات:** رفع صورة البطاقة → استخراج الاسم والرقم القومي والعنوان تلقائياً وملء الحقول (يوفر ~70% من زمن الإدخال) — يظهر كمسودة يعتمدها المستخدم
- **AI Document Classifier:** الموظف يرفع المستندات دفعة واحدة → النظام يصنفها تلقائياً (ده فيش جنائي، ده مؤهل...) ويطابقها بالـ Checklist
- **كشف التزوير الأولي:** اتساق الرقم القومي مع تاريخ الميلاد والنوع المستخرجين، وفحص جودة/اكتمال المستند
- **تنبيهات استباقية:** انتهاء مستند/عقد/فحص طبي قبلها بـ **60/30/7 يوم** عبر إيميل + WhatsApp (للموظف وللـ Personnel)
- **Data Quality Bot:** فحص دوري (أسبوعي) للسجلات الناقصة أو المتضاربة وإرسال تقرير مجمع لـ HR
