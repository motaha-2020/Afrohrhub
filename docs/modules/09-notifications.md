# الموديول 9: Notifications (محرك الإشعارات)

## الهدف

محرك إشعارات واحد متعدد القنوات تستخدمه كل الموديولات — لأن العمالة الزرقاء بلا إيميل شركة، **WhatsApp/SMS قناة أساسية وليست رفاهية**.

## القنوات

| القناة | المزود | الاستخدام |
|---|---|---|
| In-App | Supabase Realtime | كل المستخدمين داخل النظام |
| Email | Resend | White Collar، التقارير، المستندات الرسمية (العروض، الـ Hiring Email) |
| WhatsApp | WhatsApp Business API (قوالب معتمدة) | الموظفين والمرشحين — التذكيرات والتأكيدات |
| SMS | مزود مصري محلي | احتياطي للـ OTP ولمن بلا WhatsApp |

تفضيلات القنوات لكل مستخدم + سياسة Fallback (WhatsApp فشل → SMS).

## النموذج

- `notification_templates`: قوالب مزدوجة اللغة (ar/en) لكل حدث وقناة، بمتغيرات (`{{employee_name}}`، `{{due_date}}`...) — قابلة للتحرير من HR Manager. قوالب WhatsApp تُسجل لدى Meta مسبقاً
- `notifications`: سجل كل إرسال (المستلم، القناة، القالب، الحالة: queued/sent/delivered/failed، ومحاولات الإعادة)
- `scheduled_alerts`: التنبيهات الاستباقية المجدولة — يفحصها pg_cron يومياً

## كتالوج الأحداث (الحد الأدنى للـ MVP)

| المصدر | الأحداث |
|---|---|
| Recruitment | طلب بانتظار اعتمادك · مرشحون بانتظار مراجعتك · دعوة مقابلة (+تقويم) · تقييم متأخر · عرض مرسل · تذكير قبل انتهاء مهلة الـ 30 يوماً · رفض مهذب |
| Onboarding | Hiring Email للجهات · مهمة مسندة لقسمك · مستند ناقص (للموظف) · اكتمال شروط التفعيل (لـ HR) |
| Offboarding | فتح حالة · مهمة Clearance · **تصعيد: Access لم يُقطع وانقضى آخر يوم عمل** · التسوية جاهزة للاعتماد |
| Payroll | فتح مرحلة بالتقويم · سجلات مرتجعة لـ Personnel · بانتظار اعتماد Finance · **تم صرف راتبك** (WhatsApp) |
| المستندات والشهادات | **انتهاء مستند/عقد/فحص طبي/شهادة سلامة قبلها بـ 60 ثم 30 ثم 7 أيام** — للموظف والـ Personnel |
| SLA | أصفر (75%) للمسؤول · أحمر (تجاوز) تصعيد للدور الأعلى |
| Approvals | طلب بانتظارك · تذكير 24 ساعة · تصعيد 48 ساعة · قرار صدر (لصاحب الطلب) |
| Attendance/Leave | غياب أحد فريقك · طلب إجازة بانتظارك · اعتُمدت إجازتك |

## قواعد

1. **تجميع ذكي:** الأحداث منخفضة الإلحاح تتجمع في Digest يومي بدل قصف المستلم
2. **حرج لا يُجمَّع:** التصعيدات (Access، SLA أحمر، اعتمادات الصرف) فورية دائماً
3. لا بيانات راتب في نص أي إشعار خارجي — "تم صرف راتبك، التفاصيل في التطبيق" (Policy 9)
4. كل إشعار له Deep Link للشاشة المعنية
5. سجل الإرسال جزء من الـ Audit (إثبات الإخطار)

## الشاشات

مركز الإشعارات In-App (لكل مستخدم) · محرر القوالب (HR Manager) · لوحة مراقبة الإرسال والفشل (Company Admin).
